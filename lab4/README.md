## 1. Цель работы
Создать прототип AI-приложения с базовой функциональностью, спроектировать архитектуру инфраструктуры для трёх этапов жизненного цикла продукта (MVP, тестирование, production), рассчитать экономическую модель и обосновать выбор облачных сервисов Google Cloud Platform.

## 2. Описание приложения
**Название:** Jija AI  
**Тип:** B2B SaaS-приложение  
**Функциональность:** Автоматическое извлечение структурированных данных из документов (PDF, JPG) с использованием искусственного интеллекта. Пользователь загружает скан документа, система распознаёт ключевые поля (суммы, даты, контрагенты) и формирует JSON с результатами.  
**Целевая аудитория:** Бухгалтеры, юристы, операторы ввода данных.  
**Бизнес-модель:** Подписка (SaaS) с оплатой за количество обработанных документов.

### 3.2. Описание компонентов
- **Пользовательский слой:** Браузер/клиент подключается по HTTPS к Global Load Balancer + Cloud CDN для быстрой доставки фронтенда.
- **Вычислительный слой (Cloud Run):** 
  - *Этап 1:* 1 CPU, 512 MB RAM, масштабирование до 0.
  - *Этап 2:* До 10 инстансов для умеренной нагрузки.
  - *Этап 3:* Минимум 1 инстанс (избегание холодного старта), автоскейлинг до 50.
- **Сервисный слой:** 
  - *Cloud Storage:* Хранение исходных PDF и результатов (объектное хранилище).
  - *Vertex AI:* ML-инференс для анализа текста.
  - *Cloud SQL (PostgreSQL):* Хранение метаданных (появляется на Этапе 2).
- **Мониторинг:** Cloud Monitoring & Logging собирает метрики и логи со всех сервисов.

## 5. Обоснование выбора технологий  
1. **Serverless (Cloud Run) vs Virtual Machines:** Оплата только за время выполнения запросов (Request-based billing) критична на ранних этапах с непредсказуемой нагрузкой. Отсутствие операционных затрат на управление ОС компенсирует возможные накладные расходы serverless-среды.
2. **Объектное хранилище (Cloud Storage) vs Файловые системы:** В 3-5 раз дешевле для неструктурированных данных, масштабируется бесконечно без ручной настройки, поддерживает автоматические Lifecycle Policies для архивации.
3. **Управляемая БД (Cloud SQL) vs Self-hosted:** Встроенные бэкапы, репликация и автоматические обновления снижают потребность в узкоспециализированных специалистах (DBA), что критично для стартапа.
4. **Vertex AI:** Нативная интеграция с экосистемой GCP, гарантия того, что данные не покидают инфраструктуру Google (важно для B2B compliance), и единый биллинг.

# 6. Принципы проектирования  
- **FinOps:** Поэтапное наращивание инфраструктуры. Мы не инвестируем в избыточные ресурсы до валидации гипотезы, но на этапе Production инвестиции в HA и `min_instances=1` окупаются за счёт отсутствия простоев и удержания клиентов.
- **SecOps:** Принцип наименьших привилегий (IAM), шифрование данных at rest и in transit, выбор региона `europe-west1` для соответствия GDPR и 152-ФЗ.
- **DevOps:** Использование CI/CD (Cloud Build), контейнеризации и Canary Deployments (traffic splitting в Cloud Run) для безопасного обновления приложения.
